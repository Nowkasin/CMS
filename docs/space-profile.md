# ข้อมูลพื้นที่และร้านค้า

## เมนูและสิทธิ์ K2

Sidebar แสดงเมนูเดียวตาม space_profile_view; ไม่ใช้ dashboard_view อีกต่อไป
space_profile_view ใช้ดูและบันทึก 5 ช่องในรอบที่เปิด
system_settings ร่วมกับ GroupId ใน CMS_ADMIN_GROUP_IDS ใช้เข้าหน้าตั้งค่าระบบและเปิด/ปิดรอบ
ตรวจทั้งการแสดงปุ่มและ POST ฝั่ง Server กลุ่ม Admin ได้รับสิทธิ์ผ่าน K2
กลุ่มอื่นต้องกำหนดสิทธิ์แยก ไม่ตรวจชื่อกลุ่มเพื่อยกสิทธิ์อัตโนมัติ
หลังเปลี่ยนสิทธิ์ต้อง Logout/Login ใหม่

## แหล่งข้อมูล

- Contract_Location_Period: สถานะ OPEN/CLOSED ผู้เปิด/ปิด เหตุผล และ Revision_no
- รอบใหม่ที่ยังไม่มี Snapshot: SP_Contract_Location_SubArea_Test @c_date ด้วยวันสิ้นเดือน
- รายละเอียดรอบใหม่: Contract_Location_Input โดย SubArea_id และ Contract_id = 0 เป็นค่ากลาง
  หากยังไม่มีค่ากลางใช้แถวล่าสุดของพื้นที่จากระบบเดิมเป็นค่าเริ่มต้น
- รอบที่มี Snapshot: อ่านพื้นที่ สัญญา และรายละเอียดจาก Contract_Location_Snapshot
  ไม่คำนวณรายงานเดือนเก่าใหม่จาก Store

## การเปิด/ปิดรอบในหน้าเดียวกัน

เมนูตั้งค่าระบบ: Admin ที่มี system_settings เห็นตารางรอบ ปุ่มเปิดรอบ เหตุผลและ Modal
เปิดรอบเปลี่ยน Period_status เป็น OPEN เพิ่ม Revision_no และเก็บผู้ดำเนินการ/เวลา/เหตุผล
ไม่ลบ Snapshot เมื่อเปิด และมีผลร่วมกันทุกบัญชี
เมื่อมีหลายรอบ OPEN ให้รอบเก่าที่สุดเป็นรอบที่ทำงานก่อน รอบใหม่รอจนปิดรอบเก่า
แท็บจัดทำใช้ดูและแก้ไขข้อมูลรอบที่เปิด ปุ่มเปิด/ปิดอยู่ในตั้งค่าระบบเท่านั้น
ระบบไม่ใช้ Key space_profile_edit/space_period_manage แล้ว

การบันทึกรอบใหม่เขียนเฉพาะ Input ค่ากลางพื้นที่
การบันทึกรอบที่เปิดย้อนหลัง UPDATE เฉพาะ 5 ช่องใน Snapshot_date + SubArea_id ที่เลือก
ดังนั้นรายงานเดือนที่เปิดกลับมาแก้จะเปลี่ยนตามค่าที่บันทึกทันที รวมถึง Dashboard ที่อ่าน View ประวัติ
ไม่มีตารางเก็บสำเนารายงานทุก Revision; Revision_no และเหตุผลเก็บใน Period เท่านั้น
ไม่แก้ Input ล่าสุด และไม่แก้ข้อมูลเดือนอื่นจากการบันทึกย้อนหลัง
วัตถุประสงค์ที่ผู้ใช้กรอกคือ Objective_Desc_BI แยกจาก Objective_description ของสัญญา

การปิดรอบใหม่เพิ่ม Snapshot ของทุกพื้นที่ พร้อม 5 ช่องตามจริง
การปิดรอบที่เคยมี Snapshot เพียงล็อกสถานะกลับ CLOSED ไม่ INSERT Snapshot ซ้ำ
ทั้งสองกรณีตั้งผู้ปิด/วันที่ปิด และเพิ่มรอบเดือนถัดไปเป็น OPEN เฉพาะเมื่อยังไม่มี
ต้องถึงวันสิ้นเดือนและมีข้อมูลก่อนปิดรอบ แต่ไม่บังคับกรอกครบ
Modal แจ้งจำนวนพื้นที่ครบ/ยังไม่ครบ ช่องว่าง และผลการปิดรอบ
ทุกการเขียนใช้ transaction application lock ร่วมกันและ rollback เมื่อมีข้อผิดพลาด

ไม่ ALTER Table/View/Store เดิม การติดตั้งตาราง Period และสิทธิ์อยู่ใน deploy/space-period-permissions
Store บันทึกและปิดรอบเดิมผูกข้อมูลตามสัญญา จึงใช้ parameterized SQL ใน Service ของหน้านี้แทน
ไม่เขียน Contract_Location_forBI
v_Contract_Location_forBI_history อ่าน Snapshot ตามเดิม; View และ Store อื่นไม่ถูกแก้ไข

## หน้าจอ

รายการหน้าละ 20 แถว แสดงข้อมูลพื้นที่ 5 ช่องและสถานะครบ/ยังไม่ครบ
space_profile_detail เป็นฟอร์มแยก บันทึกแล้วกลับเดือนและหน้ารายการเดิม
ปุ่มเปิด/ปิดรอบอยู่ใน system_settings แยกจากหน้ารายการพื้นที่

## การตรวจสอบ

ตัวกรองในแท็บจัดทำข้อมูลและประวัติรายเดือนใช้ข้อมูลของรอบที่เลือกก่อนแบ่งหน้า:
- ประเภทธุรกิจ: `Business_Types_BI`
- สถานที่ตั้ง: `Memo_Location`
- สถานะพื้นที่ย่อย: `Status_Area`

เลือกหลายช่องเพื่อกรองร่วมกันได้ ค่าเปล่ารวมเป็น “ไม่ระบุ” ตัวกรองคงอยู่เมื่อเปลี่ยนหน้า เปิดรายละเอียด และกลับจากการบันทึก โดยไม่ Query ตาราง Master เพิ่มหรือแก้ไขข้อมูลในฐานข้อมูล

# ลบ log เข้า/ออกระบบที่เก่ากว่า 1 ปี

ตาราง `dbo.Contract_activity_log` โตตามจำนวนครั้งที่ผู้ใช้ล็อกอิน (บน DEV ณ 2026-11-26 ประมาณ 55%
ของแถวเป็นเข้า/ออกระบบ) สคริปต์นี้ลบเฉพาะเหตุการณ์กลุ่มนั้นที่เก่ากว่า 12 เดือน ผู้ใช้กำหนด 2026-11-26

| ลบเมื่อเก่ากว่า 1 ปี | เก็บไว้ตลอด |
|---|---|
| `login`, `logout`, `login_failed`, `view_as_start`, `view_as_stop` | ทุกเหตุการณ์อื่น: ยกเลิกสัญญา มิเตอร์ ระบบไฟฟ้า นำเข้า/ดาวน์โหลด Excel ส่งออก ใบแจ้งหนี้ `other_action` |

ไม่สร้าง Stored Procedure ไม่แก้ Schema ไม่แตะตารางอื่น

## ไฟล์

- `01_purge_login_logs.sql` — นับ แล้วลบทีละ 5,000 แถว (แต่ละชุดเป็น Transaction ของตัวเอง)
  - ค่าเริ่มต้น `@DryRun = 1` = นับอย่างเดียว ไม่ลบ
  - `@KeepMonths` ต่ำกว่า 12 ไม่ได้ (สคริปต์ THROW)
  - ตัดที่เที่ยงคืนของวันที่ย้อนไป 12 เดือน รันซ้ำได้ ไม่มีอะไรให้ลบก็จบเอง

## วิธีใช้

1. ตรวจนโยบายการเก็บ log ของมหาวิทยาลัยก่อน (ถ้ากำหนดนานกว่า 1 ปี ให้เพิ่ม `@KeepMonths`)
2. รันแบบ `@DryRun = 1` ครั้งแรก ดูจำนวนแถวที่จะถูกลบ
3. ตั้ง SQL Agent Job (ผู้ดูแลฐานข้อมูล):
   - Step: Transact-SQL, Database `SWU_contract`, คำสั่ง = เนื้อหาไฟล์นี้ โดยแก้ `@DryRun = 0`
   - Schedule: เดือนละครั้ง นอกเวลาทำงาน (เช่น วันที่ 1 ตี 2)
   - ไม่ต้องรันบ่อยกว่านั้น เพราะลบเฉพาะของที่เก่ากว่า 1 ปี
4. ลบแล้วกู้ไม่ได้ (ยกเว้นจาก Backup) -- ถ้าต้องการเก็บไว้ดูภายหลัง ให้ Export ก่อนลบ

## ทำไมไม่ต้องทำอย่างอื่น

- index ที่มีอยู่ (`Action_type, DateEntry`) และ (`DateEntry`) รองรับทั้งหน้า log และการลบนี้แล้ว
- ประเมิน PRD คร่าว ๆ ปีละประมาณ 70,000 แถว / 50–100 MB ยังไม่ต้องทำ Partition หรือตาราง Archive
- `Log_id` เป็น `int` (สูงสุดประมาณ 2,100 ล้าน) ยังไม่ต้องเปลี่ยนเป็น `bigint`

## ประวัติการรัน

- ยังไม่ได้รันที่ไหน (ทั้ง DEV และ PRD) -- ข้อมูลบน DEV เริ่มเก็บ 2026-10-19 ยังไม่มีอะไรเก่ากว่า 1 ปี

# ติดตั้งเมนูระบบค่าน้ำ–ค่าไฟบน PRD

ชุดนี้ใช้ติดตั้งเมนูระบบ Django CMS ลงในฐาน `SWU_contract` เดิม โดยไม่สร้าง
หรือแก้ Schema และไม่ใช้ Django migration กับตารางธุรกิจเดิม

## ผลลัพธ์ที่ต้องการ

- เพิ่มเมนูหลักระบบใหม่ด้วย key `water_electric_new`
- เพิ่มหรือปรับเมนูย่อย 7 รายการให้เป็นลูกของระบบใหม่
- หน้า `/` ส่งต่อไปยังเมนูแรกที่ผู้ใช้มีสิทธิ์ และหน้าอัปโหลดอยู่ที่ `/upload/`
- สิทธิ์แต่ละเมนูกำหนดผ่าน `SysMenuGroupAssociate`
- โค้ด Django ค้นหาเมนูหลักด้วย key จึงไม่บังคับว่า DEV และ PRD ต้องได้
  `menuId` เดียวกัน
- ไม่แก้ `menuId = 41` ของ PRD เพราะเป็นเมนู `คู่มือการใช้งาน`

## ไฟล์

1. `01_precheck.sql` — ตรวจฐาน ตาราง เมนู และกลุ่มโดยไม่เขียนข้อมูล
2. `02_apply_menu.sql` — เพิ่ม/ปรับเมนูภายใน Transaction
3. `03_apply_permissions_template.sql` — Template กำหนดสิทธิ์รายกลุ่มรายเมนู
4. `04_verify.sql` — ตรวจโครงสร้างเมนูและสิทธิ์หลังติดตั้ง
5. `05_rollback.sql` — ปิดระบบใหม่และสิทธิ์ที่เกี่ยวข้อง โดยไม่ลบแถว

## สิ่งที่ต้องแก้ก่อนรันบน PRD

เปิด `02_apply_menu.sql` แล้วกำหนด `@CmsBaseUrl` เป็น URL จริงของ PRD เช่น
`https://example.swu.ac.th/cms` ห้ามใช้ URL ngrok บน PRD

เปิด `03_apply_permissions_template.sql` แล้วเพิ่ม `GroupId` และ key ของเมนู
ที่แต่ละกลุ่มต้องใช้ กลุ่มที่ใช้เมนูย่อยต้องได้รับสิทธิ์
`water_electric_new` ด้วยเสมอ

ชุดติดตั้งไม่บังคับเลข `90` SQL Server จะสร้าง Identity ของเมนูระบบใหม่ให้
อัตโนมัติ จึงไม่ชนกับ `menuId = 41` หรือเมนูอื่นใน PRD

## ลำดับติดตั้ง

1. สำรองฐานข้อมูลและกำหนด Maintenance window
2. รัน `01_precheck.sql` และตรวจว่าไม่มี Error หรือ key ซ้ำ
3. แก้ `@CmsBaseUrl` แล้วรัน `02_apply_menu.sql`
4. กำหนดรายการสิทธิ์แล้วรัน `03_apply_permissions_template.sql`
5. Deploy โค้ดรุ่นที่ใช้ `CMS_PARENT_MENU_KEY = 'water_electric_new'`
6. Restart Django และรัน `04_verify.sql`
7. ทดสอบผู้ใช้ที่มีสิทธิ์ ผู้ใช้ที่ไม่มีสิทธิ์ และการเข้า URL โดยตรง
8. ให้ผู้ใช้ออกจากระบบแล้วเข้าสู่ระบบใหม่เพื่อโหลดสิทธิ์ลง Session อีกครั้ง

ช่วงระหว่างรัน SQL และ Deploy โค้ด เมนูอาจไม่พร้อมใช้งาน จึงควรทำภายใน
Maintenance window เดียวกัน

## Rollback

รัน `05_rollback.sql` เพื่อปิดเมนูระบบใหม่และความสัมพันธ์สิทธิ์ของเมนูใหม่
โดยไม่เปลี่ยนเมนูอื่น จากนั้น Rollback ตัวแอปเป็นรุ่นก่อนหน้าและ Restart Django

Rollback ตั้งใจไม่ `DELETE` แถวจาก `Sysmenu` เพื่อไม่กระทบ Identity และเพื่อ
เก็บหลักฐานการติดตั้งไว้ หากต้องการลบข้อมูลจริงต้องได้รับอนุมัติแยกต่างหาก
